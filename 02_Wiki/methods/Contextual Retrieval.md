# Contextual Retrieval

> **TL;DR** Prepend a short LLM-generated context summary to each chunk before embedding and BM25 indexing, so isolated chunks retain the document-level information needed to be retrieved correctly — reducing top-20 retrieval failures by 49%, and 67% when combined with reranking.

## Problem it solves
In standard [[Chunking|chunk-then-embed]] RAG, chunks are embedded in isolation. A chunk like *"The company's revenue grew by 3% over the previous quarter."* loses the company name and time period, making it unretrievable for a query like *"ACME Corp Q2 2023 revenue growth"*. [[01_Sources/web_clips/Contextual Retrieval in AI Systems]]

## Key idea
Before indexing, prepend a **50–100 token context blurb** — generated by an LLM given the full document and the chunk — to each chunk. This context is prepended to both the embedding input (*Contextual Embeddings*) and the BM25 index (*Contextual BM25*). [[01_Sources/web_clips/Contextual Retrieval in AI Systems]]

Example transformation:
```
Original: "The company's revenue grew by 3% over the previous quarter."

Contextualized: "This chunk is from an SEC filing on ACME Corp's performance in
Q2 2023; the previous quarter's revenue was $314 million. The company's revenue
grew by 3% over the previous quarter."
```

## Pipeline / Steps

**Indexing (offline):**
1. For each chunk, call Claude with the full document + chunk and ask for a succinct situating context (50–100 tokens).
2. Prepend the context to the chunk text.
3. Embed the contextualized chunk → store in vector index.
4. Also index the contextualized chunk in a BM25 index.

**Retrieval (online):**
1. Query → top-K from BM25 (exact + keyword matches).
2. Query → top-K from embedding index (semantic matches).
3. Combine and deduplicate using rank fusion (RRF).
4. Optionally rerank the fused set with a cross-encoder (e.g., Cohere Rerank).
5. Pass top-K to the LLM.

### Context generation prompt (Claude 3 Haiku)
```
<document>
{{WHOLE_DOCUMENT}}
</document>
Here is the chunk we want to situate within the whole document
<chunk>
{{CHUNK_CONTENT}}
</chunk>
Please give a short succinct context to situate this chunk within the overall
document for the purposes of improving search retrieval of the chunk. Answer
only with the succinct context and nothing else.
```

## Reported results
Evaluated across codebases, fiction, ArXiv papers, and science papers. Metric: `1 − recall@20` (fraction of relevant chunks *not* retrieved in top 20). [[01_Sources/web_clips/Contextual Retrieval in AI Systems]]

| Configuration | Failure rate | Reduction |
|---------------|-------------|-----------|
| Baseline (embeddings only) | 5.7% | — |
| Contextual Embeddings only | 3.7% | **−35%** |
| Contextual Embeddings + Contextual BM25 | 2.9% | **−49%** |
| Contextual Embeddings + Contextual BM25 + Reranking | 1.9% | **−67%** |

Best embedding models tested: **Gemini Text 004** and **Voyage** (outperformed others). Best k: 20 > 10 > 5.

## Cost
With Claude prompt caching (full document cached once, referenced per chunk):  
**$1.02 per million document tokens** to generate contextualized chunks. [[01_Sources/web_clips/Contextual Retrieval in AI Systems]]

## Comparison with alternatives
| Method | Anthropic finding |
|--------|-----------------|
| Generic document summaries prepended | Very limited gains |

| Summary-based indexing (LlamaIndex) | Low performance |

## Implementation considerations
- **Chunk boundaries**: size and overlap choices still matter — contextual prepending doesn't replace good chunking strategy. [[01_Sources/web_clips/Contextual Retrieval in AI Systems]]
- **Domain-specific prompts**: custom contextualiser prompts (including glossaries) may outperform the generic prompt.
- **Number of chunks**: always run evals — 20 chunks consistently outperformed 10 and 5 in Anthropic's tests.

## When to use / when not to
- ✅ Mixed-reference corpora (SEC filings, legal docs, technical manuals) where chunks lose entity context.
- ✅ [[Hybrid Search]] already in the pipeline — Contextual BM25 is an easy drop-in improvement.
- ✅ Latency budget allows per-chunk LLM calls at indexing time (one-time, offline cost).
- ❌ Knowledge base < 200k tokens (~500 pages) — just load it all into the prompt with caching.
- ❌ Corpora where chunks are self-contained (e.g., FAQ pairs, product descriptions).

## Related / alternatives
