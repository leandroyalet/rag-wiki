# E5

> **TL;DR** Microsoft's family of text embedding models (EmbEddings from bidirEctional Encoder rEpresentations), trained with weakly-supervised contrastive learning on large web text pairs — strong across MTEB tasks, especially retrieval.

## Description
E5 (Wang et al., Microsoft 2022) are bi-encoder [[Embeddings]] models built on a BERT/RoBERTa backbone and fine-tuned with a contrastive objective on weakly labelled (query, passage) pairs mined from the web (CCPairs dataset). A second stage of supervised fine-tuning on high-quality datasets (MS MARCO, NQ, etc.) yields the final models.

### Key design: instruction prefix
E5 requires prepending task-specific instructions to queries at inference time:
- Retrieval query: `"query: <text>"`
- Passage: `"passage: <text>"`
- For **e5-mistral-7b** (LLM-backbone variant): richer natural-language instructions.

Omitting the prefix degrades performance significantly.

### Model variants
| Variant | Params | Dim | Notes |
|---------|--------|-----|-------|
| e5-small | ~33M | 384 | Low latency |
| e5-base | ~110M | 768 | Default general-purpose |
| e5-large | ~335M | 1024 | Higher accuracy |
| e5-large-v2 | ~335M | 1024 | Improved training |
| e5-mistral-7b-instruct | ~7B | 4096 | LLM backbone; top MTEB scores |
| multilingual-e5-large | ~560M | 1024 | 100+ languages |

## When to use it
- ✅ Strong general-purpose retrieval baseline — consistently top-10 on [[MTEB]] Retrieval.
- ✅ Multilingual needs: `multilingual-e5-large` covers 100+ languages.
- ✅ High-quality retrieval at moderate size: `e5-large-v2` is a good quality/cost trade-off.
- ❌ Inference without instruction prefixes — results degrade without the `"query:"/"passage:"` convention.
- ❌ Embedding short texts without context — prefix adds overhead for simple use cases.
